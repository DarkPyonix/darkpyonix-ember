Your first conversation

From an empty launcher to an answered approval

This page starts a session on the main server, sends it a message and answers the agent's first approval request. It assumes ember-server and the client are running, as set up in Install.

Before you start

  • At least one agent CLI is installed on the main server and logged in as the user that runs ember-server. With no accounts configured, a session uses that login.
  • The project folder exists on the main server. A session starts on the main server, and Claude Code and Antigravity refuse to start in a folder that is not there.

Projects

A project is a name that groups sessions, and the computers that serve it are assigned to the project. You do not create it separately: you name it in the first session's dialog, and the server records it. On an empty launcher the client shows "No conversations yet" and a New session button; on a project card, "New session in this project" starts one there.

The same is available over the API, which is what the client calls: POST /api/projects with {"name": "my-project"}.

Starting a session

The New session dialog asks for:

FieldWhat to enter
ProjectAn existing project, or "New project…" and then a Project name.
Folder on the computerThe absolute path of the project, for example /Users/me/src/my-project. The agent's working directory.
Model (optional)Empty uses the agent's own default model.
Title (optional)Shown in the launcher; you can rename the session later.
AgentThe agents the server detected as installed, for example claude-code or codex.
Account"Automatic (the server's router chooses)", or one of the agent's accounts.
Computer"The main server (default)", or a registered computer with its reachability.

Start creates the session and opens it. The client remembers the agent, account, computer, model and folder per project, so the next session in that project starts from the same choices.

A session is always created on the main server. If you picked another computer, the client moves the session there before your first message. If that move fails, the session stays on the main server and the client says so: "Started on the main server: could not switch computer (…)".

Agents and accounts

Each agent can have several accounts on the main server. An account is a private configuration directory under accounts/ in the server's data directory, so two accounts of one agent never share a login or settings, and the agent binary is never patched. With Automatic, the server picks the agent's account with the fewest tokens used today, skipping accounts that are rate-limited or logged out. With no accounts at all, the session uses the server user's own login.

The client lists accounts but cannot create them yet, so you add one through the API. The answer's login field holds the exact login command, with the account's directory set. Run that command on the main server as the user that runs ember-server:

For Codex the command is codex login with CODEX_HOME set; on a headless server add --device-auth. Antigravity accounts are not supported yet, because agy has no configuration-directory variable. ACP agents such as OMP use the login of their own CLI. Per-agent details are on the Agents page.

Sending a message

Type in the composer at the bottom of the conversation. Enter sends and Shift+Enter starts a new line. The agent's reply streams in, with a card for every tool call and its result. The header shows the session's computer ("On …"), its status and the Open IDE button.

While a turn is running you can keep typing. The composer then says "Queue a message for the next turn": queued messages are sent in order when the turn ends, and a badge counts them. Stop interrupts the running turn.

Answering approvals

When the agent wants to run a tool that needs your permission, the conversation shows a card "tool wants approval" with the tool's input, and the header shows how many approvals are waiting. In the launcher, "waiting for approval" outranks "running", so you can spot such a session from the project list.

ButtonEffect
Allow onceRuns this one call.
Always allowRuns it, and allows this kind of tool for the rest of the session.
DenyRefuses the call; the agent sees the refusal.

A request that is still open when the turn ends is marked "Not answered before the turn ended". Antigravity has no approval channel of its own, so Ember asks through a hook, and an approval left unanswered for 58 minutes is denied; see Agents. A mode that approves everything without asking is specified but not offered by the client yet Planned (#73).

Leaving and coming back

Close the client at any time. The session lives on the main server, so a running turn finishes without you, and any client that opens the session later sees the whole result. Two clients can have the same session open and both see live output.

A session nobody is viewing releases its agent process after EMBER_IDLE_SECS (300 seconds by default). Your next message starts the agent again with its own resume (--resume for Claude Code, a thread resume for Codex), so the agent keeps its context. A session open in a client is kept alive. If the main server restarts during a turn, that session is marked idle and resumes the same way.

Keeping sessions in order

Each session row in the launcher has Pin, Archive, Rename and Export. These are stored on the server, so a second client sees them at once. Export writes a self-contained file of the transcript into the client's exports/ folder. Search covers the text of every session's messages on the server; each word matches as a prefix, so 오류 finds 오류가.
