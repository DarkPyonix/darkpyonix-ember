Install

Build Ember from source

Ember is three programs: ember-server on the main server, ember-node on every other computer, and the client ember-app wherever you sit. There are no releases or installers yet Planned (#72), so each one is built with cargo from a checkout.

What you need

  • macOS or Linux. ember-node uses Unix PTYs and signals, so it does not build on Windows. Ember is developed on macOS; CI builds and tests the server and node crates on Linux (Ubuntu).
  • A Rust toolchain with cargo, from rustup. The client needs Rust 1.85 or newer, because it uses the 2024 edition like dioxus-compose.
  • A C compiler, because the server compiles SQLite into itself.
  • The agent CLIs, on the main server only: claude, codex, agy or omp, installed the way each vendor documents and logged in as the user that will run ember-server. Ember finds them on PATH and lists a missing one as not installed rather than failing.

Get the code

Work lands on the develop branch; main does not carry the code yet. Each crate under crates/ is its own cargo project with its own Cargo.lock (there is no workspace), so you build inside the crate's folder.

ember server, on the main server

The build produces three programs in target/release/: ember-server, ember-exec and ember-a2a. Keep them in one directory. ember-server looks for the other two next to its own binary: without ember-exec, Claude Code sessions cannot run on other computers, and without ember-a2a, agents cannot message each other.

At start it logs ember server listening on http://127.0.0.1:8740. Check it from the same machine:

The HTTP listener has no login

Anyone who can reach EMBER_LISTEN can use every route, including accounts, devices and the hub registration. Keep it on loopback (the default) or on a network you trust. The authenticated path is the peer-to-peer transport, which admits only devices on the server's allow-list (Computers and the hub). To use the client from another machine today, forward the port over SSH: ssh -N -L 8740:127.0.0.1:8740 you@mini.local.

Building with the project mount

Partial When a Claude Code session works on another computer, its file tools (Read, Edit, Write, Glob, Grep) need that computer's project folder on the main server's disk. The project mount provides it, and it is a build feature, because it pulls in an NFS or FUSE implementation. It is written but not yet run on real hardware (#6).

Without either feature the server still runs. Claude Code's Bash tool still runs on the other computer, but its file tools need the project path to exist on the main server.

Settings

Everything is configured through environment variables. The ones you are most likely to set:

VariableDefaultMeaning
EMBER_DATA_DIR~/.emberWhere the database, keys, accounts and browser profiles live.
EMBER_LISTEN127.0.0.1:8740The HTTP listener.
EMBER_IDLE_SECS300Release an agent process after this long without activity. The next message resumes it.
EMBER_CLAUDE_BIN, EMBER_CODEX_BIN, EMBER_AGY_BINclaude, codex, agy on PATHWhich agent CLI to run.
EMBER_ACP_AGENTSnoneACP agents to offer, as JSON, for example ["omp"]. See Agents.
EMBER_TRANSPORToff1 binds the peer-to-peer transport. Needed for computers added by peer address and for the hub.
EMBER_HUB_URLhttps://darkpyonix.devThe hub; off disables it. Used only with EMBER_TRANSPORT=1. The default moves to the hub's own subdomain (#62).
EMBER_RELAY_URLthe hub's relayRelay server(s) for the transport.
EMBER_MOUNTautonfs, fuse or off; auto uses whichever feature the build has.
EMBER_A2Aon0 starts agent-to-agent messaging switched off.
EMBER_CHROME_BINfound on the machineThe browser for remote browsing.
RUST_LOGinfoLog filter, for example RUST_LOG=debug.

The full list, with every variable the server reads, is the comment at the top of crates/server/src/main.rs.

What it stores

Path in EMBER_DATA_DIRWhat
ember.dbSQLite: sessions and transcripts, projects, computers, accounts, A2A queues, schedules.
secret.keyEncrypts the secrets stored in ember.db (API keys, hub tokens). Back it up together with ember.db; one is useless without the other.
accounts/<id>/Each account's own agent configuration directory, with its login.
agy/One private folder per Antigravity session (its hook and rules).
browser/<project>/profileRemote browser profiles: cookies, storage, logins.
transport.keyThe server's peer identity, created with EMBER_TRANSPORT=1.

ember node, on each computer

Only computers other than the main server need a node; the main server's own disk is always available as the computer local. Build it on the computer that will run it:

The build produces ember-node and ember-term (the terminal client described in Persistent terminals). The node refuses to start without EMBER_NODE_TOKEN, because every request except a health check must carry it. It logs ember node listening on http://127.0.0.1:8741.

That default address is reachable only from the same machine. You have two ways to let the main server in. Over HTTP, set EMBER_NODE_LISTEN to an address the main server can reach, on a network you trust, because the token travels unencrypted. Over the peer-to-peer transport, set EMBER_NODE_TRANSPORT=1, which needs no open port. Computers and the hub walks through both.

VariableDefaultMeaning
EMBER_NODE_TOKENrequiredThe bearer token ember-server presents.
EMBER_NODE_LISTEN127.0.0.1:8741The HTTP listener.
EMBER_NODE_ROOTS$HOMEColon-separated folders the node may touch. File operations and working directories outside them are refused.
EMBER_NODE_STATE_DIR~/.ember/nodeTerminal state, keys and the hub registration.
EMBER_NODE_TRANSPORToff1 also serves the API over the transport; only serves it there instead of TCP.
EMBER_NODE_ALLOWED_PEERSnonePeer ids of the servers allowed in over the transport (also read from allowed-peers in the state directory).
EMBER_NODE_CODEX_BINcodex on PATHCodex sessions on this computer run codex exec-server here, so Codex must be installed on the node too.
EMBER_NODE_EGRESSonoff refuses remote-browser traffic through this computer.

The state directory holds local.json (how programs on this computer find the node), transport.key (its peer identity), allowed-peers and, once registered, hub.json. The full list of variables is the comment at the top of crates/node/src/main.rs.

The client

Partial The desktop client is a native window drawn by dioxus-compose, with no webview. It runs against ember-server, but its layout has not yet been checked on a real display, and it speaks only HTTP for now (#9).

The client depends on dioxus-compose by git, pinned to one commit, and dioxus-compose's build fetches the matching Compose renderer. If it cannot get one, build the renderer from dioxus-compose yourself and set DIOXUS_COMPOSE_RENDERER_DIR to its absolute path. That variable is checked first, and nothing is downloaded when it is set.

VariableDefaultMeaning
EMBER_SERVER_URLhttp://127.0.0.1:8740The main server.
EMBER_DATA_DIR<OS data dir>/emberThe client's cache (client-cache.json), preferences (prefs.json) and exports/. The OS data directory is ~/Library/Application Support on macOS and ~/.local/share on Linux.
EMBER_LOGwarn,ember_app=info,ember_client=infoLog filter.
DIOXUS_COMPOSE_RENDERER_DIRdownloadUse a renderer you built.

EMBER_DATA_DIR has the same name as the server's variable. If you start both from one shell on one machine, set it per command rather than exporting it, or the client writes its cache into the server's data directory.

The smallest setup

One Mac is enough to start: run ember-server and the client on it, with claude or codex logged in. Sessions then run on the main server itself. Add a node on a second computer when you want to work there.
