Troubleshooting

What Ember prints when something is wrong

Every message on this page is quoted from the code. Find the one you see, and the text beside it says what it means and what to do. Most problems are one of three things: a program that is not where the server looks for it, a computer the server cannot reach, or a path that does not exist where the agent runs.

Where the logs are

ember-server and ember-node write their logs to the terminal they run in (standard output). They write no log file, so redirect the output if you want to keep it. RUST_LOG sets the level for both, for example RUST_LOG=debug; the default is info. The client logs to its terminal too, filtered by EMBER_LOG.

Warnings at start are worth reading: the server says there which optional pieces it could not find (ember-exec, ember-a2a, a browser) and which features are off.

The client

It exits at once with "Set EMBER_SERVER_URL"

ember-app: …. Set EMBER_SERVER_URL to the main server, e.g. http://127.0.0.1:8740 means the URL could not be parsed. Use a full URL with the scheme, such as http://127.0.0.1:8740. The exit code is 2.

It shows old data and nothing updates

The client draws its cached projects and sessions before the server answers, so a window with content does not prove the server is reachable. Check the health route above from the machine running the client. If the server runs elsewhere, remember it listens on loopback by default (see the SSH forward in Install).

The build stops in dioxus-compose

The client's build fetches a Compose renderer that matches the pinned dioxus-compose commit. If it cannot, build the renderer from dioxus-compose and set DIOXUS_COMPOSE_RENDERER_DIR to its absolute path. A renderer built from another schema stops the build with "this renderer was generated from a different schema than this crate", and a variable that points at an empty folder stops it with "DIOXUS_COMPOSE_RENDERER_DIR is set to …, but no renderer is there".

Starting a session

"agent … is not available on this server"

The agent's CLI was not found on the main server. Install it for the user that runs ember-server, or point the server at it with EMBER_CLAUDE_BIN, EMBER_CODEX_BIN or EMBER_AGY_BIN. An ACP agent must also be listed in EMBER_ACP_AGENTS. GET /api/v1/agents shows what the server detected and which versions.

"working directory … does not exist on the ember server"

The full text is "working directory … does not exist on the ember server (on another computer it is mounted here when the project mount is enabled; see EMBER_MOUNT)". A Claude Code or Antigravity session runs in that folder on the main server. Create it, or fix the path in "Folder on the computer". For a session on another computer, build the server with the project mount (Computers and the hub).

"Started on the main server: could not switch computer (…)"

The session was created, but moving it to the computer you picked failed. The reason in the parentheses is one of the switch errors below. The session works on the main server; switch it again once the computer answers.

Every new session is refused with an account reason

When an agent has accounts but none is available (all rate-limited or logged out), the server refuses to start a session rather than fall back to another login, and gives the reason. GET /api/v1/accounts/route?agent=claude-code shows what the router would pick now and why. POST /api/v1/accounts/{id}/check runs the agent's own login status command, and POST /api/v1/accounts/{id}/clear-limit clears a rate-limit mark.

Agents

Antigravity: "Operation not permitted" on shell writes

Partial On macOS, with agy 1.2.16 and --sandbox (Ember's default), commands such as touch fail with Operation not permitted even inside the project, while agy's own file-writing tool works. The cause is being investigated with --sandbox kept on (#65). EMBER_AGY_SANDBOX=0 drops the flag, at the cost of agy's own sandbox.

Antigravity: "Approval for … timed out; retry."

An Antigravity approval was not answered within 58 minutes, so Ember denied it before agy's hook timed out. Send the request again.

Agents cannot message each other

The server logs ember-a2a not found next to the server binary; agents cannot use A2A. Keep ember-a2a beside ember-server. Also check that the server was not started with EMBER_A2A=0.

Other features

  • remote browser unavailable: no Chrome/Chromium found (EMBER_CHROME_BIN): install Chrome or Chromium on the main server, or set EMBER_CHROME_BIN. See Remote browser.
  • "The Ember IDE arrives with the editor core (M8). Use VS Code or Gateway for now.": Ember's own IDE window is not built yet (#32). See Opening an IDE.
  • … session(s) were mid-turn at shutdown; marked idle for resume at server start is not an error: those sessions resume with your next message.

Known macOS notes

  • Mount points under /home. On macOS /home is an automount, so a node path such as /home/pi/proj cannot simply be created on a Mac main server. scripts/ember-mount-setup.sh handles it (it edits /etc/auto_master); a new top-level folder such as /srv needs /etc/synthetic.conf and a reboot.
  • NFS without root. The macOS mount relies on mount_nfs working without sudo on a folder the user owns. That is documented upstream but not yet verified on Ember's Mac mini (#6).
  • Claude Code accounts and the keychain. Claude Code keeps a login in the macOS login keychain, so log an account out with its own auth logout command before deleting it.
  • The client's look. The client has run against a live server on macOS, but nobody has yet checked its layout on a real display (#9).
