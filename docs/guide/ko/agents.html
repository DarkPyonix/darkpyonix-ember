에이전트

에이전트

Ember는 각 에이전트의 수정하지 않은 CLI를 메인 서버에서, 그 에이전트 자체의 비대화형 프로토콜로 실행합니다. 에이전트 설정, 모델, 세션 ID는 원래대로 동작합니다. Ember는 노트북 한 대의 CLI 하나로는 할 수 없는 것을 더합니다. 여러 계정, 공유 MCP 서버, 예약, 그리고 서로 메시지를 주고받는 에이전트입니다.

서버는 시작할 때와 요청이 있을 때 설치된 에이전트와 그 버전을 찾습니다 (GET /api/v1/agents). 없는 에이전트는 오류가 아니라 미설치로 표시합니다. 각 에이전트의 바이너리는 EMBER_CLAUDE_BIN, EMBER_CODEX_BIN, EMBER_AGY_BIN, EMBER_OMP_BIN 으로 지정하고, 지정하지 않으면 PATH 에서 이름으로 찾습니다.

유휴 세션은 EMBER_IDLE_SECS(기본 300) 뒤에 에이전트 프로세스를 내려놓습니다. 다음 메시지가 오면 에이전트 자체의 재개 기능으로 다시 시작하므로, 대화는 하던 곳에서 이어집니다. 이 페이지의 REST 경로는 지금 코드가 제공하는 그대로 적었습니다. #63 이 /api/v1/... 을 /api/... 로 바꿉니다.

Claude Code 구현

  • 승인. 권한 요청은 하나하나 승인 카드가 됩니다. 이번만 허용, 항상 허용, 거부 중에서 고릅니다. "항상 허용"은 그 프로세스가 사는 동안 그 도구에 적용됩니다. 이후 같은 도구 요청에는 곧바로 답하고, 도구 호출은 대화에 그대로 보입니다.
  • 중단과 재개. 중단하면 턴이 깔끔하게 끝납니다. 내려놓았거나 재시작한 세션은 --resume 으로 돌아옵니다.
  • 계정. 계정마다 자기 CLAUDE_CONFIG_DIR 을 씁니다. 계정을 보십시오.
  • 다른 컴퓨터. 셸 명령은 ember-exec 심을 거쳐 세션의 컴퓨터에서 돕니다. 파일 도구는 같은 경로에 마운트된 컴퓨터의 프로젝트를 봅니다 (EMBER_MOUNT: auto, nfs, fuse, off. 서버를 mount-nfs 나 mount-fuse 기능으로 빌드해야 합니다).

어댑터는 Claude Code 2.1.288과 녹화한 실제 세션으로 확인했습니다.

Codex 구현

Ember는 codex app-server 를 실행하고 stdio 위의 JSON-RPC로 대화합니다. 스레드 ID가 곧 세션 ID라서 Codex 자체의 재개가 동작합니다.

  • 턴 도중의 메시지. Codex가 일하는 중에 보낸 메시지는 Codex 자체 클라이언트처럼 turn/steer 로 실행 중인 턴에 더합니다.
  • 승인. 명령, 파일 변경, 권한 요청이 승인 카드가 됩니다.
  • 설정. Codex 자체의 승인 정책, 샌드박스, 모델, config.toml 은 원래대로 적용됩니다.
  • 다른 컴퓨터. Ember는 Codex의 실험 기능인 environment/add 로 컴퓨터를 등록해, Codex가 거기서 도구를 돌리게 합니다. 실제 턴의 셸과 패치가 원격에서 실행되는지는 아직 확인하지 않았습니다.

프로토콜은 codex-cli 0.155.1에서 읽었고, 녹화한 실제 세션과 대조했습니다.

ChatGPT로 로그인 부분

직접 호스팅하는 ember server는 ChatGPT 계정으로 로그인할 수 있습니다. 그러면 Codex 토큰 사용량에 더해 ChatGPT Plus나 Pro 요금제도 쓸 수 있습니다. OpenAI는 이것을 오픈 소스이면서 로컬에서 호스팅하는 앱에만 허용합니다. 그래서 EMBER_HOSTED=1 이면 꺼지고, darkpyonix.dev를 통해서는 절대 제공하지 않습니다.

  1. POST /api/v1/chatgpt/signin 이 인증 URL을 돌려줍니다. 브라우저에서 엽니다.
  2. OpenAI는 서버의 http://127.0.0.1:<port>/auth/callback 으로 돌려보냅니다 (EMBER_CHATGPT_REDIRECT_PORT, 기본값은 서버 포트).
  3. 브라우저가 다른 기기에서 돌면 그 주소는 서버에 닿지 않습니다. 마지막 URL을 POST /api/v1/chatgpt/signin/complete 에 붙여 넣습니다.

토큰은 암호화해 저장하고 API가 돌려주지 않습니다. 주간 한도는 사용자가 ChatGPT 설정에서 정하며, 그것을 알려 주는 API는 없습니다. 로그인과 토큰 처리는 구현되어 있고, 세션에서 요금제를 쓰는 일과 한도 표시는 아직 하지 않았습니다 (#16).

Antigravity 부분

Antigravity의 print 모드는 권한을 물을 수 없고, 권한이 필요한 도구를 조용히 거절합니다. 그래서 Ember는 agy 자체의 확인 없이 실행하고 Ember 자체의 PreToolUse 훅을 유일한 관문으로 삼습니다. 훅은 세션마다 <data dir>/agy/ 아래의 전용 폴더에 있습니다. ~/.gemini 나 프로젝트에는 아무것도 쓰지 않으므로, 사용자 자신의 agy 세션은 영향을 받지 않습니다.

  • 모든 도구 호출이 훅을 거칩니다. 워크스페이스 안의 읽기 전용 도구는 통과하고, 나머지는 승인 카드가 됩니다.
  • 훅은 allow 나 deny 만 답합니다. 어떤 오류든(서버에 닿지 않음, 모르는 토큰, 이상한 응답) deny 가 됩니다.
  • 답하지 않은 카드는 agy 자체의 훅 제한 시간보다 먼저, 58분 뒤에 거부되고 "Approval for tool timed out; retry." 알림이 뜹니다.
  • 턴을 시작할 때마다 Ember는 agy가 훅을 읽어 들였는지 확인합니다. 아니면 턴을 거절합니다.
  • 실행마다 새 토큰을 쓰고, 끝나면 폐기합니다. 턴을 끝내거나 중단하면 대기 중인 카드를 모두 거부합니다.

버전 고정. 이 규칙은 agy 1.2.16 에서 테스트했고, 이 버전에 고정합니다. 다른 버전은 알림과 함께 읽기 전용으로 돕니다. 워크스페이스 안의 읽기 전용 도구만 허용하고, 나머지는 묻지 않고 거부합니다. 고정 버전은 새 버전에서 테스트를 통과한 뒤에만 옮깁니다.

샌드박스. --sandbox 는 켜져 있습니다(EMBER_AGY_SANDBOX=0 으로 끔). 1.2.16에서 샌드박스가 켜져 있으면 셸 명령은 프로젝트 안에서도 쓰기를 못 하고, 파일 편집 도구는 씁니다. 원인은 #65 에서 조사하고 있습니다.

아직 지원하지 않는 것: 계정(agy는 로그인을 ~/.gemini 에 두고, 옮길 변수가 없습니다), 다른 컴퓨터에서의 세션, 실행 중인 턴에 메시지 더하기.

OMP와 다른 ACP 에이전트 부분

Agent Client Protocol(ACP, 버전 1)을 쓰는 에이전트는 범용 어댑터 하나로 돕니다. 컴파일해 넣는 것이 아니라 설정으로 추가하고, EMBER_ACP_AGENTS(JSON)나 EMBER_ACP_AGENTS_FILE(같은 JSON을 담은 파일)을 씁니다.

문자열은 프리셋입니다. 프리셋 omp 는 omp acp 를 실행합니다. 객체에는 name 과 command 가 필요하고, args, model_args, instructions_args, version_args, env 를 더할 수 있습니다. 각 에이전트는 설정한 이름으로 에이전트 종류에 나타납니다.

  • 권한 요청은 승인 카드가 됩니다(이번만 허용, 항상 허용, 거부).
  • 에이전트가 ACP로 보내는 파일 읽기, 쓰기와 터미널 명령은 세션의 컴퓨터에서 그 ember node를 거쳐 돕니다.
  • ACP에는 턴 도중에 메시지를 더하는 기능이 없어서, 턴 도중에 보낸 메시지는 다음 턴으로 미룹니다.
  • 계정 분리는 아직 없습니다. 서버에서 에이전트 자체 CLI로 로그인합니다.

어댑터는 가짜 ACP 에이전트로 테스트합니다. 테스트 서버에 OMP가 설치되어 있지 않아서 실제 OMP로는 아직 돌려 보지 않았습니다 (#53).

계정과 사용량 라우팅 구현

메인 서버는 Claude Code와 Codex에 대해 에이전트마다 여러 계정을 둘 수 있습니다. 계정은 <data dir>/accounts/<id> 디렉터리이고, CLI 자체의 변수 CLAUDE_CONFIG_DIR 이나 CODEX_HOME 으로 그곳을 가리킵니다. 그러면 어느 CLI도 고치지 않고 인증 정보, 설정, 원래 세션 파일이 서로 분리됩니다.

  1. 계정을 만듭니다: POST /api/v1/accounts 에 {"agent": "claude-code", "label": "work"}.
  2. 응답에 정확한 로그인 명령이 들어 있습니다. 예: CLAUDE_CONFIG_DIR=<dir> claude auth login. ember가 실행되는 사용자로 서버에서 실행합니다. Ember는 로그인을 자동화하지 않습니다. 화면 없는 서버의 Codex라면 --device-auth 를 붙입니다.
  3. POST /api/v1/accounts/{id}/check 는 에이전트의 읽기 전용 상태 명령을 실행합니다.

새 세션은 고른 계정을 씁니다. 고르지 않으면 라우터가 사용량 제한에 걸리지도, 로그아웃되지도 않은 계정 가운데 오늘(UTC) 토큰을 가장 적게 쓴 계정을 고르고, 같으면 기본 계정, 그다음 오래된 계정을 고릅니다. 고른 계정과 그 이유는 세션에 저장되고 조용히 바뀌지 않습니다. 사용량 제한에 걸린 계정은 초기화 시점까지 건너뛰고, 그 계정에서 턴이 끝까지 완료되면 표시가 풀립니다. GET /api/v1/accounts/route?agent=… 는 지금 라우터가 무엇을 고를지, GET /api/v1/usage?days=7 은 계정별 일별 토큰을 보여 줍니다.

서버 환경 변수의 키

서버 자신의 환경에 있는 ANTHROPIC_API_KEY, OPENAI_API_KEY, CODEX_API_KEY 는 모든 에이전트 프로세스에 전달되어 계정의 로그인을 덮어씁니다. 서버는 시작할 때 이것을 경고합니다.

API 키 제공자(OpenAI 호환이나 공급사 API)는 POST /api/v1/providers 로 추가합니다. 키는 암호화해 저장하고 돌려주지 않습니다.

중앙 MCP 레지스트리 구현

MCP 서버를 한 번 추가하면, MCP를 지원하는 모든 에이전트 세션이 프로세스를 시작할 때 그것을 받습니다. Claude Code는 --mcp-config 로, Codex는 -c mcp_servers.<name> 덮어쓰기로, Antigravity는 세션 폴더로, ACP 에이전트는 session/new 로 받습니다.

  • 환경 변수 값은 비밀로 다룹니다. 암호화해 저장하고, 돌려주지 않으며(이름만 돌려줌), 명령줄에 넣지 않고, 로그에 남기지 않습니다.
  • "enabled": false 로 PATCH 하면 지우지 않고 끕니다.
  • 변경은 각 에이전트 프로세스가 다음에 시작할 때부터 적용됩니다.

예약 프롬프트 구현

예약은 시간대가 있는 cron 식, 고정 간격, 또는 한 번만 프롬프트를 보냅니다. 실행할 때마다 기존 세션을 이어 가거나 프로젝트에 새 세션을 시작합니다. 프롬프트는 사용자 메시지처럼 [ember schedule] 머리줄을 달고 들어갑니다.

  • 서버가 꺼져 있던 동안 놓친 시점은 조용히 실행하지 않습니다. 놓침으로 기록하고 알림을 남깁니다. catch_up 을 켜면 놓친 것 중 마지막 하나만 실행합니다.
  • cron 시각은 일광 절약 시간 변경을 거쳐도 시간대를 따릅니다. 두 번 오는 시각에는 한 번만 실행합니다.
  • 예약은 /api/v1/schedules 로 관리합니다(만들기, 일시 정지, 재개, 지금 실행, 실행 기록). 에이전트도 대화 중에 만들 수 있습니다.

A2A 메시지 구현

세션끼리는 공급사, 컴퓨터, 계정이 달라도 메시지를 주고받을 수 있습니다. 모든 에이전트 프로세스는 EMBER_URL, EMBER_SESSION_ID, 세션마다 다른 EMBER_RUNTIME_TOKEN 과 ember-a2a 명령 사용법을 받습니다. 에이전트를 고치지 않습니다.

  • 메시지는 사용자 메시지처럼 대상에 들어가고, 보낸 쪽과 답장 참조를 적은 [ember a2a] 머리줄이 붙습니다.
  • 바쁜 대상은 다음 턴 경계에서 받습니다. 잠든 대상은 깨웁니다. 전달하지 못한 메시지는 서버 재시작 뒤에도 남습니다.
  • 루프 방지: 10분 안에 세션당 최대 20개, 세션 쌍당 최대 10개입니다. 서로 끝없이 답하라고 지시받은 두 에이전트는 알림과 함께 멈춥니다.
  • A2A는 서버 전체(EMBER_A2A=0 또는 PUT /api/v1/a2a/settings)나 세션 단위(/api/v1/sessions/{id}/a2a)로 끌 수 있습니다. 꺼진 세션과 주고받는 메시지는 이유와 함께 거절합니다.

팀과 @@멘션 구현

세션은 팀을 이끌 수 있습니다. 처음 team spawn 을 부른 세션이 리더가 되고, 팀원은 같은 프로젝트의 새 세션으로 리더가 고른 에이전트, 계정, 컴퓨터를 씁니다. 팀원은 자기 승인을 자기 세션에서 답합니다.

  • 활성 팀원은 최대 8명입니다. 한 세션은 한 팀에만 속하고, 팀 안에 팀을 두지 않습니다.
  • 팀원을 만들고 끝내는 것은 리더만 합니다. 작업은 누구나 추가하고, 팀원은 자기 작업이나 배정되지 않은 작업만 고칩니다.
  • 활성 팀원은 자기 팀에만 메시지를 보낼 수 있고, 자기 팀만 그 팀원에게 보낼 수 있습니다.
  • 대화 화면에는 팀원, 실시간 상태, 작업 목록을 보여 주는 팀 패널이 있습니다.

입력창에서 @@ 로 다른 세션을 멘션합니다. @@<id>, @@<title>, @@"<title with spaces>" 형식입니다. @@ 를 치면 맞는 세션이 보입니다. 메시지 자체는 이 대화에 그대로 남고, 멘션된 세션마다 이 세션이 보낸 A2A 메시지로 사본이 갑니다. 그래서 멘션된 쪽은 호출 한 번으로 여기에 답할 수 있습니다. 찾지 못한 멘션이 있어도 잃는 것은 없습니다. 아직 확인하지 않은 것: 서로 다른 컴퓨터와 계정에서 도는 실제 Claude Code와 Codex 세션으로 이루어진 팀.
