원격 브라우저

원격 브라우저

Ember는 트래픽이 내 컴퓨터 중 하나에서 나가는 브라우저를 띄울 수 있습니다. 그래서 웹 페이지는 그 컴퓨터의 IP 주소와 로컬 네트워크를 봅니다. 쿠키, 로그인, 방문 기록은 메인 서버에 남으므로 컴퓨터를 바꿔도 같은 로그인 상태의 브라우저를 씁니다. 에이전트도 같은 브라우저를 다룰 수 있고, 사용자는 그것을 지켜볼 수 있습니다.

현재 상태

부분 서버 쪽은 구현되어 있고 부분별로 테스트합니다. 브라우저, 프로필, 컴퓨터를 통한 송출, 화면 스트림, 에이전트 중계가 그것입니다. 실제 Chrome으로 실제 node를 거치는 송출은 아직 돌려 보지 않았고, Ember 클라이언트에는 아직 브라우저 화면이 없습니다. 진행은 #12 에서 확인합니다.

프로젝트마다 브라우저 하나

프로젝트마다 메인 서버에 헤드리스 Chromium 하나가 1280×800 뷰포트로 돕니다. 무언가가 처음 열거나 볼 때 시작합니다.

  • 브라우저 바이너리는 EMBER_CHROME_BIN 입니다. 없으면 서버가 Google Chrome, Chromium, Chrome for Testing을 찾고, 다음으로 PATH 의 google-chrome 이나 chromium, 마지막으로 Playwright 캐시의 가장 새 Chromium을 찾습니다. 하나도 없으면 서버는 원격 브라우저 없이 시작하고 로그에 그렇게 적습니다.
  • EMBER_BROWSER_HEADFUL=1 은 디버깅용으로 실제 창을 띄웁니다.

REST 경로에는 버전이 없어서 모두 /api/ 로 시작합니다.

트래픽이 나가는 곳

송출 경로는 프로젝트마다 고르고, 세 종류가 있습니다.

direct
메인 서버 자신의 네트워크입니다.
proxy
프록시 URL입니다. socks5://, socks4://, http://, https:// 를 쓰고, 인증 정보는 넣지 않습니다.
computer
등록된 컴퓨터입니다. 트래픽이 그 컴퓨터의 ember node를 통해 나갑니다. local 은 direct와 같습니다.

송출 경로를 바꾸면 Chrome을 쿠키가 기록되도록 정상 종료한 뒤 같은 프로필로 다시 띄웁니다. 그래서 로그인이 유지됩니다. 고른 값은 서버 데이터베이스에 저장되고, 서버를 재시작한 뒤에도 다시 적용됩니다.

컴퓨터를 고르면 경로는 사슬 모양입니다. Chrome은 메인 서버 루프백의 SOCKS5 프록시를 쓰고, 메인 서버는 그 바이트를 연결마다 WebSocket 하나로 node의 /egress 에 복사하며, node가 실제 연결을 엽니다.

  • 호스트 이름은 그 컴퓨터에서 풉니다. 그래서 컴퓨터의 로컬 DNS 이름이 동작합니다.
  • 루프백도 프록시를 거치므로, 브라우저의 localhost 는 그 컴퓨터의 localhost 입니다. 거기서 도는 개발 서버에 닿을 수 있습니다.
  • 컴퓨터에 닿을 수 없으면 브라우저 시작이 실패합니다. direct로 슬쩍 돌아가지 않습니다. 그러면 메인 서버의 IP가 조용히 드러나기 때문입니다.
  • 어떤 프로젝트의 브라우저가 쓰는 컴퓨터는 제거할 수 없습니다(409).

컴퓨터 쪽 ember node는 기본적으로 모든 목적지를 허용합니다. 그 컴퓨터의 localhost 와 LAN에 닿아야 하기 때문입니다. 범위를 좁히려면 EMBER_NODE_EGRESS_DENY 에 private,link-local,loopback 이나 CIDR 범위를 적습니다. EMBER_NODE_EGRESS=off 는 송출을 모두 거절합니다.

프로필

프로필(쿠키, 저장소, 로그인, 방문 기록)은 메인 서버의 <EMBER_DATA_DIR>/browser/<project>/profile 에 있습니다. 어느 컴퓨터로 송출하든 같은 프로필입니다. 한 프로젝트의 브라우저 데이터를 지우려면 다음과 같이 합니다.

브라우저 속 에이전트 부분

에이전트는 메인 서버에서 브라우저 옆에 돌므로, /api/browsers/{project}/cdp 의 DevTools 중계를 통해 브라우저에 닿습니다. Ember는 그 중계를 가리키는, 수정하지 않은 기성 DevTools MCP 서버를 에이전트에게 줍니다. 기본값은 꺼짐이고, 서버에서 켭니다.

켜면 모든 에이전트 세션이 자기 프로젝트 브라우저를 가리키는 ember-browser 라는 MCP 서버와 함께 시작합니다.

  • chrome-devtools 는 npx -y chrome-devtools-mcp@latest --wsEndpoint=<relay> 를 실행합니다.
  • playwright 는 npx -y @playwright/mcp@latest --cdp-endpoint=<relay> 를 실행합니다.
  • Claude Code는 --mcp-config 로, Codex는 -c mcp_servers.ember-browser.* 덮어쓰기로, Antigravity는 세션 폴더의 mcp_config.json 으로, ACP 에이전트는 session/new 로 받습니다. 사용자 자신의 MCP 서버는 그대로 남습니다.
  • 서버에 npx 도 bunx 도 없으면 경고와 함께 이 설정을 무시합니다.

처음 실행할 때 패키지를 내려받으므로, Ember는 MCP 시작 제한 시간을 90초로 늘립니다. 에이전트를 손으로 연결하고 싶다면 GET /api/browsers/{project}/agent-config 가 같은 설정을 돌려줍니다. 송출 경로를 바꾸면 중계 연결이 닫히고, MCP 서버는 다음 도구 호출 때 다시 연결합니다. Antigravity 자체의 브라우저 도구는 Ember와 함께 테스트하지 않았습니다.

보기와 넘겨받기

브라우저는 클라이언트 안의 웹 페이지가 아니라 그림으로 보입니다. 런처와 대화 화면에는 웹뷰가 절대 들어가면 안 되기 때문입니다. 보는 쪽은 GET /api/browsers/{project}/view WebSocket에 접속합니다. JPEG 프레임이 나오고, 마우스, 키보드, 이동 입력이 들어갑니다. 프레임은 누군가 보고 있을 때만 보내고, 모든 시청자가 스트림 하나를 함께 씁니다.

  • 에이전트가 명령을 보내는 동안 상태에 agent_active 가 켜집니다(마지막 명령 뒤 3초간). 그래서 화면에서 에이전트가 일하는 중임을 보여 줄 수 있습니다.
  • 비밀번호를 입력할 때처럼 사용자가 넘겨받을 수 있습니다. 넘겨받은 동안 에이전트의 명령은 기다리고, 놓으면 에이전트가 하던 곳에서 이어 갑니다.
  • Ember 클라이언트에는 아직 브라우저 화면이 없습니다 (#12). 휴대폰도 같은 스트림을 쓸 수 있지만, 지금은 터치를 마우스 입력으로 바꾸고 모든 시청자가 1280×800 뷰포트 하나를 함께 씁니다.

알아 둘 점

  • 브라우저의 원래 DevTools 포트는 메인 서버 루프백에서 인증 없이 열려 있습니다. 에이전트는 중계를 써야 합니다.
  • 컴퓨터용 SOCKS5 리스너도 루프백에서 인증이 없습니다. 리스너가 도는 동안 메인 서버의 어느 로컬 프로세스든 그 컴퓨터의 송출 경로를 쓸 수 있습니다.
  • Ember 자체 API에는 아직 인증이 없습니다. 서버는 믿을 수 있는 네트워크에 두십시오.
  • 다른 컴퓨터에서 일하는 Codex 세션의 경우, Codex가 중계에 닿는 곳에서 MCP 서버를 띄우는지는 확인하지 않았습니다.
