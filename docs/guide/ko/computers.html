컴퓨터와 허브

세션을 다른 컴퓨터에서 일하게 하기

컴퓨터는 ember-node 를 실행하고 메인 서버에 등록되면 Ember에 합류합니다. 등록 방법은 세 가지입니다: HTTP 주소, 피어 주소, 또는 darkpyonix.dev 계정에서 고르기. 등록한 뒤에는 어떤 세션이든 그 컴퓨터로 옮길 수 있습니다.

지금은 API로

클라이언트는 컴퓨터를 보여 주고, 프로젝트에 배정하고, 세션을 컴퓨터 사이에서 옮기지만, 컴퓨터를 추가하지는 아직 못합니다. 추가는 메인 서버에서 curl 로 ember-server 의 HTTP API를 불러서 합니다. 경로는 지금 /api/v1 아래에 있고 /api 로 옮겨 갑니다 계획 (#63).

피어 주소로

P2P 전송을 쓰면 노드에 열어 둘 포트가 필요 없고, 양쪽이 각자의 키로 인증됩니다. 전송을 켜고 시작하면 양쪽 모두 자기 신원을 출력합니다.

  1. 메인 서버를 EMBER_TRANSPORT=1 로 시작합니다. ember server peer id: … 와 ember server peer addr: … 가 출력됩니다.
  2. 컴퓨터에서 그 서버 피어 id를 노드의 허용 목록에 넣고, 전송을 켜서 노드를 시작합니다. 목록이 비어 있으면 노드는 no allowed peers: every transport connection will be refused 라고 경고합니다. 실행 중인 노드는 SIGHUP 을 받으면 allowed-peers 를 다시 읽고, 목록에서 빠진 피어의 연결을 끊습니다.
  3. 노드를 피어 id로, 또는 주소 힌트까지 담긴 출력된 peer addr 객체 전체로 등록합니다:

이 경로에서도 노드 토큰은 키와 함께 쓰는 두 번째 인증 요소로 여전히 필요합니다. 부분 전송은 메모리 내 네트워크로 테스트했고, 실제 네트워크(집, 사무실, LTE, 대칭형 NAT)에서의 측정은 남아 있습니다 (#10).

darkpyonix.dev 허브를 통해

부분 허브를 쓰면 모든 장치가 일회용 코드로 내 GitHub 계정에 합류합니다. 그 뒤 각 장치는 허브에 자기 주소를 올리고 다른 장치를 허브에서 찾으므로, 아무도 주소를 입력하지 않습니다. Ember 쪽은 가짜 허브로 테스트했지만 실제 허브에서는 아직 실행하지 않았고, 허브 주소가 https://darkpyonix.dev 에서 아직 정해지지 않은 별도 서브도메인으로 바뀌는 중입니다(#62). 그 변경이 들어오기 전까지는 내장 기본값이 이전 주소이므로, 서버와 모든 노드에서 EMBER_HUB_URL 을 허브 주소로 설정하세요.

1. 메인 서버 연결하기

허브는 전송이 있어야 하므로 서버를 EMBER_TRANSPORT=1 로 실행합니다.

GitHub으로 darkpyonix.dev에 로그인한 브라우저에서 verification_uri_complete 를 열고 승인합니다. 메인 서버는 반드시 브라우저에서 승인해야 합니다. 승인한 뒤에는 GET /api/v1/hub 로 등록 상태를 볼 수 있습니다. 연결을 기다리는 동안 서버가 재시작되면 같은 연결을 이어서 기다립니다.

2. 각 컴퓨터 등록하기

브라우저에서 승인하거나, 메인 서버가 승인하게 합니다. 컴퓨터의 연결은 그 계정의 메인 서버가 승인할 수 있기 때문입니다:

등록 정보는 ~/.ember/node/hub.json 에 저장됩니다. 노드를 EMBER_NODE_TRANSPORT=1 로 다시 시작하거나 SIGHUP 을 보내면, 노드가 허브를 통해 자기 주소를 올립니다. allowed-peers 를 고치지 않고 내 계정의 메인 서버를 들이려면 EMBER_NODE_HUB_ALLOW_SERVERS=1 도 설정합니다. 상태는 언제든 ember-node hub status 로 볼 수 있습니다.

3. 컴퓨터로 추가하기

허브는 노드 토큰을 전달하지 않으므로 여기서도 토큰이 필요합니다. 컴퓨터는 피어 id만으로 저장되고, 서버는 허브의 디렉터리를 통해 그 주소를 찾습니다.

프로젝트에 배정하기

런처 아래쪽에는 컴퓨터가 연결 상태("Online", "Offline", 아직 모르면 "Checking…")와 맡은 프로젝트와 함께 나열됩니다. 프로젝트를 고른 상태에서는 컴퓨터마다 "Assign to project" 스위치가 있습니다. 한 프로젝트에 여러 컴퓨터를, 한 컴퓨터에 여러 프로젝트를 배정할 수 있습니다. API로는 PUT /api/v1/projects/{name}/computers/{computer_id} 이고, 같은 경로에 DELETE 를 보내면 배정을 풉니다.

세션의 컴퓨터 전환

대화 머리글에는 "On computer"가 있습니다. 그것을 눌러 다른 컴퓨터를 고릅니다. 턴이 진행 중이거나 승인을 기다리는 동안에는 전환이 거부됩니다. 진행 중인 도구 호출이 이전 컴퓨터의 것이기 때문입니다. 먼저 답하거나 턴을 멈추세요. 대상 컴퓨터가 응답하지 않을 때도 거부됩니다.

전환하면 클라이언트가 "Switched to name. The agent is told with your next message."라고 알려 줍니다. 에이전트의 환경 설명(운영체제, 셸, 툴체인)은 덧붙이지 않고 교체되며, 안내문이 파일을 다시 읽고 명령을 다시 실행한 뒤에 그 내용을 믿으라고 에이전트에게 알립니다. 에이전트별로 도구가 컴퓨터에 닿는 방식은 다음과 같습니다:

에이전트다른 컴퓨터에서
Codex모든 도구가 codex exec-server 를 거쳐 노드에서 실행되므로, 그 컴퓨터에도 Codex가 설치되어 있어야 합니다.
Claude CodeBash는 ember-exec 를 거쳐 노드에서 실행됩니다. Read, Edit, Write, Glob, Grep은 메인 서버의 디스크에서 동작하며, 프로젝트 마운트가 노드의 폴더를 그곳에 붙여 줍니다.
OMP와 그 밖의 ACP 에이전트에이전트가 Ember에 요청하는 파일 읽기, 쓰기, 터미널이 노드에서 실행됩니다.
Antigravity아직 지원하지 않습니다: "Antigravity sessions cannot run on another computer yet".

부분 Codex와 Claude Code의 Bash 도구는 같은 Mac에서 노드를 별도 컴퓨터로 등록해 확인했습니다. 물리적으로 다른 두 컴퓨터 사이의 전환은 아직 확인하지 않았습니다 (#6).

프로젝트 마운트

부분 Claude Code의 파일 도구는 메인 서버의 claude 안에서 실행됩니다. 그래서 세션이 다른 컴퓨터에 있으면, Ember는 그 컴퓨터의 프로젝트 폴더를 메인 서버의 같은 절대 경로에 마운트합니다. 그러면 도구가 올바른 파일을 보고, 대화 기록의 경로도 사실로 남습니다. 마운트는 작성은 끝났지만 실제 Mac mini나 Raspberry Pi에서 아직 실행하지 않았습니다(#6).

  • 빌드: macOS 메인 서버는 --features mount-nfs, Linux는 --features mount-fuse(설치). EMBER_MOUNT=off 로 끌 수 있습니다.
  • 마운트 지점: 서버 사용자가 그 경로를 만들 수 있어야 합니다. 만들 수 없다면(다른 사용자의 홈, macOS의 /home, 새 최상위 폴더) scripts/ember-mount-setup.sh <path> 를 한 번 실행합니다. 이 스크립트는 sudo 명령을 실행하기 전에 하나씩 출력하고, --dry-run 이면 출력만 합니다.
  • 기존 폴더: 같은 경로에 비어 있지 않은 로컬 폴더가 있으면 그 위에 마운트하지 않습니다. EMBER_MOUNT_SHADOW=1 이면 마운트합니다.
  • 범위: 세션의 폴더만 마운트합니다. 중첩된 프로젝트 폴더와, 같은 경로를 두 컴퓨터가 제공하는 경우는 거부합니다.
  • 최신성: 쓰기는 즉시 노드로 갑니다. 노드에서 다른 프로그램이 바꾼 내용은 1초쯤 뒤에 보입니다(EMBER_MOUNT_TTL_MS, 기본 1000).
  • 장애: 노드 호출마다 4초 기한이 있어서, 컴퓨터가 끊기면 멈추는 대신 I/O 오류로 드러납니다.

컴퓨터 제거

DELETE /api/v1/computers/{id} 는 컴퓨터와 그 프로젝트 배정을 지웁니다. 그 컴퓨터에 있는 세션이 있거나 어떤 프로젝트의 원격 브라우저가 그 컴퓨터를 거쳐 나가는 동안에는 거부되므로, 먼저 옮기세요. 허브에서 빠지려면 컴퓨터에서 ember-node hub forget 을, 메인 서버에서는 DELETE /api/v1/hub/registration 을 실행합니다. --local 이나 ?local=1 을 붙이면 여기서만 등록을 잊고, 장치는 계정에 남습니다.
