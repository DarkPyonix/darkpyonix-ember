첫 대화

빈 런처에서 첫 승인까지

이 페이지에서는 메인 서버에서 세션을 시작하고, 메시지를 보내고, 에이전트의 첫 승인 요청에 답합니다. 설치대로 ember-server 와 클라이언트가 실행 중이라고 가정합니다.

시작하기 전에

  • 메인 서버에 에이전트 CLI가 하나 이상 설치되어 있고, ember-server 를 실행하는 사용자로 로그인되어 있어야 합니다. 계정을 따로 설정하지 않으면 세션은 그 로그인을 씁니다.
  • 프로젝트 폴더가 메인 서버에 있어야 합니다. 세션은 메인 서버에서 시작하며, Claude Code와 Antigravity는 없는 폴더에서는 시작하지 않습니다.

프로젝트

프로젝트는 세션을 묶는 이름이며, 그 프로젝트를 맡는 컴퓨터도 프로젝트에 배정됩니다. 따로 만들 필요는 없습니다. 첫 세션의 대화 상자에서 이름을 정하면 서버가 기록합니다. 런처가 비어 있으면 클라이언트는 "No conversations yet"와 New session 버튼을 보여 주고, 프로젝트 카드의 "New session in this project"는 그 프로젝트에서 세션을 시작합니다.

클라이언트가 부르는 API로도 같은 일을 할 수 있습니다: POST /api/v1/projects 에 {"name": "my-project"}.

세션 시작

New session 대화 상자는 다음을 묻습니다:

항목입력할 것
Project기존 프로젝트, 또는 "New project…"를 고른 뒤 Project name.
Folder on the computer프로젝트의 절대 경로. 예: /Users/me/src/my-project. 에이전트의 작업 디렉터리가 됩니다.
Model (optional)비워 두면 에이전트의 기본 모델을 씁니다.
Title (optional)런처에 표시됩니다. 나중에 이름을 바꿀 수 있습니다.
Agent서버가 설치되어 있다고 감지한 에이전트. 예: claude-code, codex.
Account"Automatic (the server's router chooses)", 또는 그 에이전트의 계정 하나.
Computer"The main server (default)", 또는 연결 상태가 함께 표시되는 등록된 컴퓨터.

Start 를 누르면 세션이 만들어지고 열립니다. 클라이언트는 프로젝트마다 에이전트, 계정, 컴퓨터, 모델, 폴더를 기억하므로, 그 프로젝트의 다음 세션은 같은 선택에서 시작합니다.

세션은 언제나 메인 서버에서 만들어집니다. 다른 컴퓨터를 골랐다면 클라이언트가 첫 메시지 전에 세션을 그곳으로 옮깁니다. 옮기지 못하면 세션은 메인 서버에 남고, 클라이언트가 "Started on the main server: could not switch computer (…)"라고 알려 줍니다.

에이전트와 계정

에이전트마다 메인 서버에 계정을 여러 개 둘 수 있습니다. 계정은 서버 데이터 디렉터리의 accounts/ 아래에 있는 전용 설정 디렉터리이므로, 한 에이전트의 두 계정이 로그인이나 설정을 공유하지 않고, 에이전트 바이너리도 고치지 않습니다. Automatic 이면 서버가 그 에이전트의 계정 중 사용 한도에 걸렸거나 로그아웃된 계정을 빼고, 오늘 토큰을 가장 적게 쓴 계정을 고릅니다. 계정이 하나도 없으면 세션은 서버 사용자의 로그인을 씁니다.

클라이언트는 계정을 보여 주기만 하고 아직 만들지는 못하므로, 계정은 API로 추가합니다. 응답의 login 필드에 계정 디렉터리가 지정된 로그인 명령이 그대로 들어 있습니다. 그 명령을 메인 서버에서 ember-server 를 실행하는 사용자로 실행합니다:

Codex라면 CODEX_HOME 을 지정한 codex login 이며, 화면 없는 서버에서는 --device-auth 를 붙입니다. agy 에는 설정 디렉터리 변수가 없어서 Antigravity 계정은 아직 지원하지 않습니다. OMP 같은 ACP 에이전트는 자기 CLI의 로그인을 씁니다. 에이전트별 자세한 내용은 에이전트 페이지에 있습니다.

메시지 보내기

대화 아래쪽 입력창에 씁니다. Enter 는 보내기, Shift+Enter 는 줄 바꿈입니다. 에이전트의 답이 스트리밍으로 들어오며, 도구 호출과 그 결과마다 카드가 붙습니다. 머리글에는 세션의 컴퓨터("On …"), 상태, Open IDE 버튼이 있습니다.

턴이 진행 중이어도 계속 쓸 수 있습니다. 그때 입력창에는 "Queue a message for the next turn"이 표시되고, 대기열의 메시지는 턴이 끝나면 순서대로 보내지며 배지가 그 수를 셉니다. Stop 은 진행 중인 턴을 중단합니다.

승인에 답하기

에이전트가 허락이 필요한 도구를 쓰려고 하면, 대화에 도구 입력이 담긴 "tool wants approval" 카드가 나타나고, 머리글에 기다리는 승인 수가 표시됩니다. 런처에서는 "승인 대기"가 "실행 중"보다 우선해 표시되므로, 프로젝트 목록에서 바로 그런 세션을 찾을 수 있습니다.

버튼효과
Allow once이 호출 한 번만 실행합니다.
Always allow실행하고, 세션이 끝날 때까지 이 종류의 도구를 허용합니다.
Deny호출을 거부합니다. 에이전트는 거부되었다는 사실을 봅니다.

턴이 끝날 때까지 답하지 않은 요청에는 "Not answered before the turn ended"가 표시됩니다. Antigravity에는 자체 승인 경로가 없어서 Ember가 훅으로 묻고, 58분 동안 답이 없는 승인은 거부합니다(에이전트 참고). 묻지 않고 모두 승인하는 모드는 명세에는 있지만 클라이언트에는 아직 없습니다 계획 (#73).

떠났다가 돌아오기

클라이언트는 언제든 닫아도 됩니다. 세션은 메인 서버에 있으므로 진행 중인 턴은 혼자 끝나고, 나중에 그 세션을 여는 클라이언트는 결과 전체를 봅니다. 두 클라이언트가 같은 세션을 함께 열면 둘 다 실시간 출력을 봅니다.

아무도 보고 있지 않은 세션은 EMBER_IDLE_SECS(기본 300초)가 지나면 에이전트 프로세스를 내려놓습니다. 다음 메시지가 에이전트 고유의 이어 가기(Claude Code는 --resume, Codex는 스레드 재개)로 다시 시작하므로 에이전트는 맥락을 잃지 않습니다. 클라이언트에 열려 있는 세션은 살아 있게 유지됩니다. 턴 도중에 메인 서버가 재시작되면 그 세션은 유휴 상태로 표시되고 같은 방식으로 이어집니다.

세션 정리

런처의 각 세션 줄에는 Pin, Archive, Rename, Export 가 있습니다. 서버에 저장되므로 다른 클라이언트에도 바로 반영됩니다. Export는 대화 기록을 독립된 파일로 클라이언트의 exports/ 폴더에 씁니다. 검색은 서버에 있는 모든 세션의 메시지 본문을 대상으로 하고, 각 단어가 접두어로 맞으므로 오류 로 오류가 를 찾습니다.
