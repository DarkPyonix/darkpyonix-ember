개요

하나의 AI, 여러 컴퓨터

Ember는 코딩 에이전트를 위한 개발 환경입니다. Claude Code, Codex, Antigravity, OMP가 모든 대화를 보관하는 메인 서버 한 대에서 실행됩니다. 에이전트의 도구는 작업에 필요한 컴퓨터에서 동작하고, 대화는 도중에 다른 컴퓨터로 옮겨 갈 수 있습니다.

초기 단계의 프로젝트

Ember에는 아직 릴리스가 없어서 소스에서 직접 빌드합니다(설치 참고). 이 가이드는 2026-10-03 기준 develop 브랜치의 코드를 설명합니다. 아직 끝나지 않은 기능에는 상태(구현 부분 계획)와 그 기능을 추적하는 이슈를 붙였습니다.

대화가 먼저

메인 화면에는 프로젝트가 나열됩니다. 각 프로젝트는 대화 세션과 그 상태(실행 중, 승인 대기, 완료, 실패)를 보여 줍니다. 프로젝트 아래에는 내 컴퓨터들이 온라인 여부와 함께 표시됩니다.

에이전트를 이끌 때는 대화를 엽니다. 메시지를 보내고, 승인 요청에 답하고, 진행 중인 턴을 중단하고, 세션을 다른 컴퓨터로 옮깁니다. IDE는 코드를 읽어야 할 때 대화에서 여는 것이지 앱의 중심이 아닙니다. 에이전트와 일하는 시간 대부분은 편집기에 타이핑하는 시간이 아니라 에이전트를 지켜보고 방향을 잡는 시간이기 때문입니다.

메인 서버 한 대

메인 서버는 Mac mini나 Raspberry Pi처럼 켜 두는 기계이며, ember-server 를 실행합니다. 모든 에이전트 CLI가 이곳에서 화면 없이, 제조사가 배포한 그대로 수정 없이 실행됩니다. 모든 대화 기록과 계정도 이곳에 있습니다.

그래서 대화가 더 이상 그것을 시작한 컴퓨터에 묶이지 않습니다. 클라이언트를 닫아도 세션은 메인 서버에서 계속 실행됩니다. 나중에 같은 컴퓨터든 다른 컴퓨터든 클라이언트를 다시 열면 대화는 두고 간 자리에 그대로 있습니다.

위치가진 것갖지 않는 것
메인 서버(ember-server)모든 에이전트 프로세스, 모든 대화 기록과 에이전트 자체 세션 파일, 계정과 자격 증명, 프로젝트, 컴퓨터, A2A 대기열, 예약 작업, 브라우저 프로필기준본으로서의 프로젝트 소스
컴퓨터(ember-node)프로젝트 파일, 그리고 도구가 띄운 프로세스: 빌드, 테스트, 서버, 터미널에이전트 CLI, 대화 기록, 에이전트 자격 증명
클라이언트(ember-app)메인 서버가 마지막으로 보낸 내용의 캐시(즉시 시작하기 위한 것)기준이 되는 데이터

컴퓨터, 그리고 컴퓨터 사이의 이동

컴퓨터는 프로젝트 파일을 갖고 빌드를 돌리는 기계입니다. 각 컴퓨터는 ember-node 를 실행합니다. 이 작은 데몬은 자신을 쓰는 세션을 대신해 도구 동작을 수행합니다: 파일 읽기와 쓰기, 검색, 명령 실행, 터미널, 브라우저 트래픽입니다. 에이전트를 실행하지도, 대화 기록을 저장하지도 않습니다. 메인 서버 자신도 언제나 컴퓨터로 쓸 수 있으며, API에서는 local, 클라이언트에서는 "The main server"라고 부릅니다.

세션은 프로젝트에 속하고, 현재 컴퓨터는 바뀔 수 있는 속성입니다. 전환한 뒤 다음 도구 호출은 새 컴퓨터에서 실행됩니다. 다음 메시지와 함께 에이전트에게 컴퓨터가 바뀌었으니 앞서 본 파일 내용과 명령 출력을 다시 읽으라는 안내가 전달됩니다. 그 내용은 이전 기계를 설명한 것이기 때문입니다.

  1. 내 메시지가 메인 서버의 세션에 도착합니다.
  2. 에이전트 CLI가 파일을 읽거나 명령을 실행하기로 합니다.
  3. Ember가 그 동작을 세션의 현재 컴퓨터로 보내고, 그곳의 ember-node 가 수행한 뒤 결과를 스트리밍으로 돌려줍니다. 에이전트에게는 자기 기계에서 실행된 것처럼 보입니다.
  4. 이벤트가 저장되고, 그 세션을 열어 둔 모든 클라이언트에 전달됩니다.

에이전트끼리의 대화

세션끼리는 제조사, 컴퓨터, 계정이 달라도 직접 메시지를 주고받을 수 있습니다. 모든 에이전트는 자기 세션 전용 토큰과 함께 작은 CLI인 ember-a2a 를 받습니다. 전달된 메시지는 사용자 메시지와 같은 길로 대상 세션에 들어가며, 보낸 세션과 답장 참조를 적은 머리말이 붙습니다. 세션별, 쌍별 전송 한도가 있어서 두 에이전트가 끝없이 서로 답하는 일을 막습니다.

직접 다른 세션을 대화에 끌어들일 수도 있습니다. 입력창에 @@ 와 그 세션의 제목이나 id를 쓰면 됩니다. 리더 세션은 작업 목록과 메일함을 공유하는 팀원 세션을 띄울 수도 있습니다. 두 기능 모두 에이전트 페이지에서 다룹니다.

연결 방식

클라이언트는 HTTP로 ember-server 와 통신합니다. ember-server 는 각 컴퓨터에 HTTP로, 또는 iroh 기반의 P2P 전송(QUIC, 홀 펀칭, 릴레이 대체 경로)으로 연결합니다. darkpyonix.dev 허브를 쓰면 컴퓨터가 일회용 코드로 내 GitHub 계정에 합류하므로, 주소를 입력하거나 포트를 열 필요가 없습니다. 각 방법은 컴퓨터와 허브에서 설명합니다.

현재 상태

영역상태비고
세션, 대화 기록, 푸시, 검색, 내보내기구현세션 포크는 어떤 에이전트에도 아직 구현되지 않아서, 클라이언트에 포크 동작이 없습니다.
Claude Code와 Codex구현각 CLI 고유의 헤드리스 프로토콜로 구동합니다.
Antigravity부분agy 1.2.16에서 Ember의 승인 훅으로 통제합니다. --sandbox 에서 셸 쓰기가 실패합니다(#65). 메인 서버에서만 실행됩니다.
OMP와 그 밖의 ACP 에이전트부분가짜 ACP 에이전트로 테스트했고, 실제 OMP 실행은 남아 있습니다(#53).
컴퓨터와 전환부분같은 Mac에서 노드를 두 번째 컴퓨터로 등록해 Codex와 Claude Code의 Bash 도구를 확인했습니다. 물리적으로 다른 두 컴퓨터 사이의 전환은 아직 확인하지 않았습니다(#6).
프로젝트 마운트(다른 컴퓨터에서 쓰는 Claude Code 파일 도구)부분작성은 끝났지만 실제 Mac mini나 Raspberry Pi에서 아직 실행하지 않았습니다(#6).
P2P 전송부분서버, 노드, 클라이언트 크레이트에 연결했고 메모리 내 네트워크로 테스트했습니다. 실제 네트워크에서의 측정은 남아 있습니다(#10).
darkpyonix.dev 허브부분가짜 허브로 테스트했고 실제 허브로는 아직입니다. 허브 주소가 hub.darkpyonix.dev 로 옮겨 갑니다(#62).
네이티브 클라이언트부분HTTP로 ember-server 에 붙어 동작합니다. 실제 화면에서 레이아웃을 확인하지 않았고, 휴대폰 클라이언트는 아직 없습니다(#9).
IDE 열기부분대화에서 VS Code와 JetBrains Gateway를 엽니다. Ember 자체 IDE 창은 편집기 코어를 기다립니다(#32). IDE 열기를 참고하세요.
영구 터미널부분영구 터미널을 참고하세요(#26).
원격 브라우저부분원격 브라우저를 참고하세요(#12).
릴리스와 설치 프로그램계획아직 없습니다. 모든 프로그램을 cargo로 빌드합니다.

시작하기

설치

ember server, ember node, 클라이언트를 소스에서 빌드하고 실행합니다.

첫 대화

프로젝트와 세션을 만들고, 에이전트와 계정을 고르고, 메시지를 보내고, 승인에 답합니다.

컴퓨터와 허브

주소나 darkpyonix.dev로 컴퓨터를 추가하고, 세션을 그 컴퓨터로 옮깁니다.

문제 해결

Ember가 실제로 출력하는 오류 메시지와 그 뜻, 로그 위치를 정리했습니다.
