설치

소스에서 Ember 빌드하기

Ember는 세 프로그램으로 이루어집니다. 메인 서버의 ember-server, 다른 각 컴퓨터의 ember-node, 그리고 내가 앉아 있는 곳의 클라이언트 ember-app 입니다. 아직 릴리스나 설치 프로그램이 없어서 계획 (#72), 각 프로그램을 체크아웃에서 cargo로 빌드합니다.

준비물

  • macOS 또는 Linux. ember-node 는 Unix PTY와 시그널을 쓰므로 Windows에서는 빌드되지 않습니다. Ember는 macOS에서 개발하고, CI는 서버와 노드 크레이트를 Linux(Ubuntu)에서 빌드하고 테스트합니다.
  • cargo가 포함된 Rust 툴체인(rustup으로 설치). 클라이언트는 dioxus-compose처럼 2024 에디션을 쓰므로 Rust 1.85 이상이 필요합니다.
  • C 컴파일러. 서버가 SQLite를 자기 안에 컴파일해 넣기 때문입니다.
  • 에이전트 CLI, 메인 서버에만: claude, codex, agy, omp 를 각 제조사의 안내대로 설치하고, ember-server 를 실행할 사용자로 로그인해 둡니다. Ember는 PATH 에서 이들을 찾고, 없는 것은 오류 대신 "설치되지 않음"으로 표시합니다.

코드 받기

작업은 develop 브랜치에 들어갑니다. main 에는 아직 코드가 없습니다. ember/ 아래의 각 크레이트는 자기 Cargo.lock 을 가진 독립된 cargo 프로젝트이므로(워크스페이스가 없습니다), 크레이트 폴더 안에서 빌드합니다.

ember server, 메인 서버에

빌드하면 target/release/ 에 ember-server, ember-exec, ember-a2a 세 프로그램이 생깁니다. 셋을 한 디렉터리에 두세요. ember-server 는 나머지 둘을 자기 바이너리 옆에서 찾습니다. ember-exec 가 없으면 Claude Code 세션이 다른 컴퓨터에서 실행되지 못하고, ember-a2a 가 없으면 에이전트끼리 메시지를 보내지 못합니다.

시작하면 ember server listening on http://127.0.0.1:8740 을 로그에 남깁니다. 같은 기계에서 확인합니다:

HTTP 리스너에는 로그인이 없습니다

EMBER_LISTEN 에 닿을 수 있는 사람은 계정, 장치, 허브 등록을 포함한 모든 경로를 쓸 수 있습니다. 기본값인 루프백이나 믿을 수 있는 네트워크에만 두세요. 인증되는 경로는 서버의 허용 목록에 있는 장치만 받아들이는 P2P 전송입니다(컴퓨터와 허브). 지금 다른 기계에서 클라이언트를 쓰려면 SSH로 포트를 전달합니다: ssh -N -L 8740:127.0.0.1:8740 you@mini.local.

프로젝트 마운트를 넣어 빌드하기

부분 Claude Code 세션이 다른 컴퓨터에서 일할 때, 그 파일 도구(Read, Edit, Write, Glob, Grep)는 메인 서버의 디스크에서 그 컴퓨터의 프로젝트 폴더를 봐야 합니다. 프로젝트 마운트가 이를 제공하며, NFS나 FUSE 구현을 끌어오기 때문에 빌드 기능으로 나뉘어 있습니다. 작성은 끝났지만 실제 하드웨어에서는 아직 실행하지 않았습니다 (#6).

두 기능 없이도 서버는 실행됩니다. Claude Code의 Bash 도구는 여전히 다른 컴퓨터에서 실행되지만, 파일 도구를 쓰려면 프로젝트 경로가 메인 서버에도 있어야 합니다.

설정

모든 설정은 환경 변수로 합니다. 자주 쓰는 것들입니다:

변수기본값뜻
EMBER_DATA_DIR~/.ember데이터베이스, 키, 계정, 브라우저 프로필을 두는 곳.
EMBER_LISTEN127.0.0.1:8740HTTP 리스너.
EMBER_IDLE_SECS300활동이 없을 때 에이전트 프로세스를 내려놓기까지의 시간. 다음 메시지가 다시 이어 갑니다.
EMBER_CLAUDE_BIN, EMBER_CODEX_BIN, EMBER_AGY_BINPATH 의 claude, codex, agy실행할 에이전트 CLI.
EMBER_ACP_AGENTS없음제공할 ACP 에이전트, JSON으로. 예: ["omp"]. 에이전트 참고.
EMBER_TRANSPORT꺼짐1 이면 P2P 전송을 엽니다. 피어 주소로 추가한 컴퓨터와 허브에 필요합니다.
EMBER_HUB_URLhttps://darkpyonix.dev허브. off 면 끕니다. EMBER_TRANSPORT=1 일 때만 씁니다. 기본값은 허브 전용 서브도메인으로 바뀝니다(#62).
EMBER_RELAY_URL허브의 릴레이전송에 쓸 릴레이 서버.
EMBER_MOUNTautonfs, fuse, off. auto 는 빌드에 들어 있는 기능을 씁니다.
EMBER_A2A켜짐0 이면 에이전트 간 메시지를 끈 채로 시작합니다.
EMBER_CHROME_BIN기계에서 찾음원격 브라우저에 쓸 브라우저.
RUST_LOGinfo로그 필터. 예: RUST_LOG=debug.

서버가 읽는 모든 변수의 목록은 ember/server/src/main.rs 맨 위의 주석에 있습니다.

ember.dbSQLite: 세션과 대화 기록, 프로젝트, 컴퓨터, 계정, A2A 대기열, 예약 작업.
secret.keyember.db 에 저장된 비밀(API 키, 허브 토큰)을 암호화합니다. ember.db 와 함께 백업하세요. 하나만으로는 쓸모가 없습니다.
accounts/<id>/각 계정의 에이전트 설정 디렉터리와 로그인.
agy/Antigravity 세션마다 하나씩 있는 전용 폴더(훅과 규칙).
browser/<project>/profile원격 브라우저 프로필: 쿠키, 저장소, 로그인.
transport.key서버의 피어 신원. EMBER_TRANSPORT=1 일 때 만들어집니다.

ember node, 각 컴퓨터에

노드는 메인 서버가 아닌 컴퓨터에만 필요합니다. 메인 서버 자신의 디스크는 언제나 local 컴퓨터로 쓸 수 있습니다. 노드를 실행할 컴퓨터에서 빌드합니다:

빌드하면 ember-node 와 ember-term(영구 터미널에서 설명하는 터미널 클라이언트)이 생깁니다. 상태 확인을 뺀 모든 요청이 토큰을 가져와야 하므로, 노드는 EMBER_NODE_TOKEN 없이는 시작하지 않습니다. 시작하면 ember node listening on http://127.0.0.1:8741 을 로그에 남깁니다.

이 기본 주소는 같은 기계에서만 닿습니다. 메인 서버를 들이는 방법은 두 가지입니다. HTTP라면 EMBER_NODE_LISTEN 을 메인 서버가 닿을 수 있는 주소로 두되, 토큰이 암호화되지 않은 채 오가므로 믿을 수 있는 네트워크에서만 씁니다. P2P 전송이라면 EMBER_NODE_TRANSPORT=1 을 설정하며, 열어 둘 포트가 필요 없습니다. 두 방법 모두 컴퓨터와 허브에서 차례로 설명합니다.

변수기본값뜻
EMBER_NODE_TOKEN필수ember-server 가 제시하는 bearer 토큰.
EMBER_NODE_LISTEN127.0.0.1:8741HTTP 리스너.
EMBER_NODE_ROOTS$HOME노드가 다룰 수 있는 폴더(콜론으로 구분). 그 밖의 파일 작업과 작업 디렉터리는 거부합니다.
EMBER_NODE_STATE_DIR~/.ember/node터미널 상태, 키, 허브 등록.
EMBER_NODE_TRANSPORT꺼짐1 이면 API를 전송으로도 제공하고, only 면 TCP 대신 전송으로만 제공합니다.
EMBER_NODE_ALLOWED_PEERS없음전송으로 들어올 수 있는 서버의 피어 id(상태 디렉터리의 allowed-peers 에서도 읽습니다).
EMBER_NODE_CODEX_BINPATH 의 codex이 컴퓨터의 Codex 세션은 여기서 codex exec-server 를 실행하므로, 노드에도 Codex가 설치되어 있어야 합니다.
EMBER_NODE_EGRESS켜짐off 면 이 컴퓨터를 거치는 원격 브라우저 트래픽을 거부합니다.

상태 디렉터리에는 local.json(이 컴퓨터의 프로그램이 노드를 찾는 방법), transport.key(피어 신원), allowed-peers, 그리고 등록한 뒤에는 hub.json 이 들어 있습니다. 변수 전체 목록은 ember/node/src/main.rs 맨 위의 주석에 있습니다.

클라이언트

부분 데스크톱 클라이언트는 dioxus-compose가 그리는 네이티브 창이며 웹뷰가 없습니다. ember-server 에 붙어 동작하지만, 실제 화면에서 레이아웃을 아직 확인하지 않았고, 지금은 HTTP로만 통신합니다 (#9).

클라이언트는 dioxus-compose를 git으로, 한 커밋에 고정해 의존하며, dioxus-compose의 빌드가 그에 맞는 Compose 렌더러를 받아 옵니다. 받아 오지 못하면 dioxus-compose에서 렌더러를 직접 빌드하고 DIOXUS_COMPOSE_RENDERER_DIR 를 그 절대 경로로 설정합니다. 이 변수가 가장 먼저 확인되며, 설정되어 있으면 아무것도 내려받지 않습니다.

변수기본값뜻
EMBER_SERVER_URLhttp://127.0.0.1:8740메인 서버.
EMBER_DATA_DIR<OS 데이터 디렉터리>/ember클라이언트의 캐시(client-cache.json), 설정(prefs.json), exports/. OS 데이터 디렉터리는 macOS에서 ~/Library/Application Support, Linux에서 ~/.local/share 입니다.
EMBER_LOGwarn,ember_app=info,ember_client=info로그 필터.
DIOXUS_COMPOSE_RENDERER_DIR내려받음직접 빌드한 렌더러를 씁니다.

EMBER_DATA_DIR 은 서버의 변수와 이름이 같습니다. 한 기계의 한 셸에서 둘을 모두 시작한다면 export하지 말고 명령마다 따로 지정하세요. 그러지 않으면 클라이언트가 서버의 데이터 디렉터리에 캐시를 씁니다.

가장 작은 구성

시작하는 데는 Mac 한 대면 충분합니다. 그 Mac에서 ember-server 와 클라이언트를 실행하고, claude 나 codex 에 로그인해 둡니다. 그러면 세션은 메인 서버 자신에서 실행됩니다. 두 번째 컴퓨터에서 일하고 싶어질 때 그곳에 노드를 추가합니다.

  1. 터미널 하나에서 ember-server 를 시작합니다.
  2. 다른 터미널에서 클라이언트를 시작합니다.
  3. 첫 대화로 넘어갑니다.
