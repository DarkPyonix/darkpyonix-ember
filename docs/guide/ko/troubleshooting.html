문제 해결

문제가 생겼을 때 Ember가 출력하는 것

이 페이지의 메시지는 모두 코드에서 그대로 옮겼습니다. 보이는 메시지를 찾으면 옆에 그 뜻과 할 일이 있습니다. 대부분의 문제는 셋 중 하나입니다: 서버가 찾는 자리에 없는 프로그램, 서버가 닿지 못하는 컴퓨터, 에이전트가 실행되는 곳에 없는 경로.

로그 위치

ember-server 와 ember-node 는 실행 중인 터미널(표준 출력)에 로그를 씁니다. 로그 파일은 만들지 않으므로, 보관하려면 출력을 리디렉션하세요. 두 프로그램 모두 RUST_LOG 로 수준을 정하며(예: RUST_LOG=debug), 기본값은 info 입니다. 클라이언트도 자기 터미널에 로그를 쓰고, EMBER_LOG 로 거릅니다.

시작할 때의 경고는 읽어 볼 만합니다. 서버는 그때 찾지 못한 선택 요소(ember-exec, ember-a2a, 브라우저)와 꺼져 있는 기능을 알려 줍니다.

클라이언트

"Set EMBER_SERVER_URL"을 출력하고 바로 끝남

ember-app: …. Set EMBER_SERVER_URL to the main server, e.g. http://127.0.0.1:8740 은 URL을 해석하지 못했다는 뜻입니다. http://127.0.0.1:8740 처럼 스킴까지 있는 전체 URL을 쓰세요. 종료 코드는 2입니다.

오래된 데이터만 보이고 갱신되지 않음

클라이언트는 서버가 답하기 전에 캐시된 프로젝트와 세션부터 그리므로, 창에 내용이 있다고 서버에 닿는다는 뜻은 아닙니다. 클라이언트가 실행되는 기계에서 위의 상태 확인 경로를 불러 보세요. 서버가 다른 곳에서 돈다면 기본값이 루프백이라는 점을 기억하세요(설치의 SSH 전달 참고).

dioxus-compose에서 빌드가 멈춤

클라이언트의 빌드는 고정된 dioxus-compose 커밋에 맞는 Compose 렌더러를 받아 옵니다. 받지 못하면 dioxus-compose에서 렌더러를 빌드하고 DIOXUS_COMPOSE_RENDERER_DIR 를 그 절대 경로로 설정하세요. 다른 스키마로 만든 렌더러는 "this renderer was generated from a different schema than this crate"로 빌드를 멈추고, 빈 폴더를 가리키는 변수는 "DIOXUS_COMPOSE_RENDERER_DIR is set to …, but no renderer is there"로 멈춥니다.

세션 시작

"agent … is not available on this server"

메인 서버에서 그 에이전트의 CLI를 찾지 못했습니다. ember-server 를 실행하는 사용자 기준으로 설치하거나, EMBER_CLAUDE_BIN, EMBER_CODEX_BIN, EMBER_AGY_BIN 으로 서버에 위치를 알려 주세요. ACP 에이전트는 EMBER_ACP_AGENTS 에도 있어야 합니다. 서버가 감지한 에이전트와 버전은 GET /api/agents 로 볼 수 있습니다.

"working directory … does not exist on the ember server"

Claude Code의 전체 문구는 "working directory … does not exist on the ember server (on another computer it is mounted here when the project mount is enabled; see EMBER_MOUNT)"이고, Antigravity의 문구는 "server"에서 끝납니다. Claude Code와 Antigravity 세션은 메인 서버의 그 폴더에서 실행됩니다. 폴더를 만들거나 "Folder on the computer"의 경로를 고치세요. 다른 컴퓨터의 세션이라면 프로젝트 마운트를 넣어 서버를 빌드합니다 (컴퓨터와 허브).

"Started on the main server: could not switch computer (…)"

세션은 만들어졌지만 고른 컴퓨터로 옮기지 못했습니다. 괄호 안의 이유는 아래 전환 오류 중 하나입니다. 세션은 메인 서버에서 동작하니, 컴퓨터가 응답하면 다시 전환하세요.

새 세션마다 계정 이유와 함께 거부됨

에이전트에 계정이 있지만 쓸 수 있는 계정이 없으면(모두 사용 한도에 걸렸거나 로그아웃), 서버는 다른 로그인으로 넘어가지 않고 이유와 함께 세션 시작을 거부합니다. GET /api/accounts/route?agent=claude-code 는 라우터가 지금 무엇을 왜 고를지 보여 줍니다. POST /api/accounts/{id}/check 는 에이전트 자체의 로그인 상태 명령을 실행하고, POST /api/accounts/{id}/clear-limit 는 사용 한도 표시를 지웁니다.

부분 이 메시지들은 실제 하드웨어에서 아직 실행하지 않은 코드에서 나옵니다(#6).

cannot reach the hub: …네트워크와 EMBER_HUB_URL 을 확인합니다. 기본 주소는 바뀌는 중입니다(#62).
the link expired before it was approved (user code …)연결을 다시 시작하고 더 빨리 승인합니다.

state: removed from the account (…)(ember-node hub status)누군가 허브에서 이 컴퓨터를 제거해 더 이상 게시되지 않습니다. 허브에서 다시 허용한 뒤 ember-node hub register 를 실행합니다.

에이전트

Antigravity: 셸 쓰기에서 "Operation not permitted"

부분 macOS의 agy 1.2.16에서 --sandbox(Ember의 기본값)를 쓰면, touch 같은 명령이 프로젝트 안에서도 Operation not permitted 로 실패합니다. agy 자체의 파일 쓰기 도구는 동작합니다. --sandbox 를 켠 채로 원인을 조사하고 있습니다 (#65). EMBER_AGY_SANDBOX=0 이면 플래그를 빼지만, 그만큼 agy 자체의 샌드박스를 잃습니다.

Antigravity: "Approval for … timed out; retry."

Antigravity 승인에 58분 동안 답이 없어서, agy의 훅이 시간 초과되기 전에 Ember가 거부했습니다. 요청을 다시 보내세요.

에이전트끼리 메시지를 못 보냄

서버가 ember-a2a not found next to the server binary; agents cannot use A2A 를 로그에 남깁니다. ember-a2a 를 ember-server 옆에 두세요. 서버를 EMBER_A2A=0 으로 시작하지 않았는지도 확인합니다.

그 밖의 기능

  • remote browser unavailable: no Chrome/Chromium found (EMBER_CHROME_BIN): 메인 서버에 Chrome이나 Chromium을 설치하거나 EMBER_CHROME_BIN 을 설정합니다. 원격 브라우저를 참고하세요.
  • "The Ember IDE arrives with the editor core (M8). Use VS Code or Gateway for now.": Ember 자체 IDE 창은 아직 없습니다(#32). IDE 열기를 참고하세요.
  • 서버 시작 시의 … session(s) were mid-turn at shutdown; marked idle for resume 는 오류가 아닙니다. 그 세션들은 다음 메시지와 함께 이어집니다.

알려진 macOS 사항

  • /home 아래의 마운트 지점. macOS에서 /home 은 자동 마운트이므로, Mac 메인 서버에서는 /home/pi/proj 같은 노드 경로를 그냥 만들 수 없습니다. ember/server/scripts/ember-mount-setup.sh 가 이를 처리합니다(/etc/auto_master 를 고칩니다). /srv 같은 새 최상위 폴더는 /etc/synthetic.conf 와 재부팅이 필요합니다.
  • root 없는 NFS. macOS 마운트는 사용자가 소유한 폴더에서 sudo 없이 mount_nfs 가 동작한다는 점에 기대고 있습니다. 상위 프로젝트 문서에는 그렇게 나와 있지만, Ember의 Mac mini에서는 아직 확인하지 않았습니다(#6).
  • Claude Code 계정과 키체인. Claude Code는 로그인을 macOS 로그인 키체인에 보관하므로, 계정을 지우기 전에 그 계정의 auth logout 명령으로 로그아웃하세요.
  • 클라이언트의 모습. 클라이언트는 macOS에서 실제 서버에 붙어 실행된 적이 있지만, 실제 화면에서 레이아웃을 확인한 사람은 아직 없습니다(#9).
